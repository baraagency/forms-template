# Accessibility

WCAG **2.1 AA** contrast targets, screen-reader wiring, mobile touch targets, and advisory automated checks for the forms template.

## Commands

| Command | Purpose |
| --- | --- |
| `bun run test:a11y:contrast` | Token contrast audit (`scripts/a11y/check-contrast.ts`) |
| `bun run lint:a11y` | ESLint with `eslint-plugin-jsx-a11y` on `app/` |
| `bun run test:a11y` | Contrast audit + Playwright axe suite |
| `bun test app/forms/_core/__tests__/FieldError.test.tsx` | Unit tests for field error / `aria-*` helpers |

## Advisory vs strict CI

By default, contrast and CI workflows are **advisory** — they report failures but do not block merges.

To promote to a hard gate locally or in CI:

```bash
STRICT_A11Y=1 bun run test:a11y:contrast
```

Set `continue-on-error: false` in [`.github/workflows/a11y.yml`](../.github/workflows/a11y.yml) when the baseline is clean.

## Design tokens

Contrast pairs live in [`scripts/a11y/contrast-pairs.json`](../scripts/a11y/contrast-pairs.json). Documented targets are in [`.interface-design/system.md`](../.interface-design/system.md).

After changing `--body-color`, `--placeholder-color`, or other text tokens in [`app/globals.css`](../app/globals.css), re-run the contrast audit.

## Shared field patterns

| Component | Path | Role |
| --- | --- | --- |
| `FieldError` | `app/forms/_core/FieldError.tsx` | `role="alert"`, `aria-live="polite"`, stable `id` for `aria-describedby` |
| `fieldA11yProps` | `app/forms/_core/useFieldIds.ts` | `aria-invalid` + `aria-describedby` from field id + error |
| `FormValidationSummary` | `app/forms/_core/FormValidationSummary.tsx` | Top-of-form alert after failed submit |
| `FormNotice` | `app/forms/_core/FormNotice.tsx` | `error` tone (bara `Notice` lacks it) |
| `SkipToMain` | `app/forms/_core/SkipToMain.tsx` | Skip link in `app/root.tsx` |

Form controls (`CommunicationTextInput`, `FormSelectInput`, date/time pickers) accept `error`, `disabled`, and `readOnly` where applicable. State styles: `app/forms/_core/fieldStates.css`.

## Screen reader checklist

- Page shells use `<main id="main-content">` and skip link targets it.
- Settings tabs: roving `tabindex` + Arrow/Home/End via `useRovingTabIndex`.
- `PillToggle`: visually hidden native input preserves `:focus-visible` on the track.
- Invalid submit: `FormValidationSummary` + per-field `FieldError` ids.

## Mobile

Breakpoint tokens: `--bp-sm` (640px), `--bp-md` (768px), `--bp-lg` (900px), `--bp-form-cols` (700px) in `globals.css`.

Coarse pointers (`pointer: coarse`): interactive controls target **44px** min height. Playwright `mobile-chrome` (Pixel 5) project exercises layout at ~390px width.

## Read-only forms (client apps)

Template example forms disable resubmission prefill (`previousSubmissionFormData={null}`). For read-only review UIs in client forks: pass `readOnly` / `disabled` on pickers and inputs, avoid submit actions, and keep labels associated.
